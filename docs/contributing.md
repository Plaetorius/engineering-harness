# Contributing

Keep scope small and evidence-backed. Shared content must remain runtime-neutral; conditional profiles must not become universal technology mandates. Skill changes should improve routing or decisions for realistic tasks, not accumulate repeated admonitions.

Run `bash scripts/verify`. Installer changes need fake-home regression tests for affected ownership/conflict/failure behavior. New profiles need trigger boundaries, appropriate standards and representative tasks; the data/computation suite is a later collaborative design.

Do not add external dependencies, automatic hooks or model orchestration without a demonstrated need. Never include host settings, credentials, private logs or evaluation transcripts. Before publishing a contribution, inspect the complete diff for secrets, personal paths and private artifacts. Keep fixtures synthetic and verification claims evidence-based.
