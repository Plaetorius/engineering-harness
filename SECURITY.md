# Security policy

Do not put credentials, production dumps, private transcripts or installation backups in issues or pull requests. Report vulnerabilities privately through [GitHub private vulnerability reporting](https://github.com/Plaetorius/engineering-harness/security/advisories/new). Do not disclose exploit details or secrets in public issues.

The installer creates user-level instruction and skill links and private ownership state; an optional reviewed operation patches one Claude instruction-selection setting. It runs no network bootstrap or custom hooks. Review canonical content and scripts before applying. Linked content updates immediately when this checkout changes, so treat repository write access as control over future agent context.

Instructions influence models; they do not enforce isolation or guarantee security. Use native CLI permissions/sandboxing and repository CI. See [threat model](docs/security.md) and [rollback](docs/rollback.md).

Publication does not constitute a security certification. Review changes and retain native sandbox/permission protections; see the documented verification and compatibility limitations.
