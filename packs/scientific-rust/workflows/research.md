# Scientific Rust delivery

Apply only after explicit activation. Keep project equations, physical assumptions, reference implementations, datasets, thresholds and commands in the project profile and its referenced research documents. This pack supplies engineering guidance, not a validated scientific model. Load only the standards and skills relevant to the task.

For substantial numerical work, define a bounded scientific outcome: for example, one solver operation with characterized inputs, independent reference comparison, invariants, failure behavior and reproducible outputs. Identify units, conditioning, approximation/discretization assumptions and the consequence of a wrong result before implementing. Shared grids, schemas, FFI layouts, reference artifacts and accelerator resources are contracts; establish ownership before parallel work. Core Vertical Slice Delivery gates still apply.

Characterize the existing reference before porting or optimizing. Require evidence appropriate to the claim: known solutions or independent calculations, differential cases, invariants and convergence studies where applicable. Tests copied from the implementation's formulas can share its errors. Separate implementation verification from validation of the underlying model against physical/experimental evidence. When no independent reference exists, record the limitation and agree substitute evidence; do not manufacture confidence.

Resolve checks through the existing project profile. Formatting, lint and debug tests alone do not establish scientific correctness. Numerical changes normally require optimized tests, justified reference comparisons and relevant invariants/negative cases. Profile-required missing checks block acceptance; neither a successful benchmark nor compilation waives them. Read-only review remains separate from implementation.

Heavy runs require an explicit execution budget: dataset size, peak memory/disk estimate, worker/thread count, wall time, external-resource policy and stop conditions. The generic runner bounds wall time, not memory, disk, network access or cluster jobs. Use existing project/OS controls when needed; never submit paid/remote jobs, download datasets, install toolchains or start large sweeps merely because this pack is active. Prefer a representative small correctness case before a full experiment. Do not silently substitute it for a required full run.

Record source revision, exact command, toolchain, configuration, inputs, seeds, hardware, result artifacts and limitations using the [run record](../templates/research-run.md). Distinguish local success, integration checks and acceptance; report unexecuted scientific checks honestly. Keep confidential datasets, credentials and large generated artifacts out of harness commits.
